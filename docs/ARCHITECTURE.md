# Modern Armory architecture

Minecraft 1.21.1, NeoForge 21.1, GeckoLib 4.9 (root project). `versions/26.3` is a port of the
same structure; keep classes and package names parallel so changes port file by file.

The rule throughout: **one source of truth, data in catalogs, behaviour in strategies**. Nothing
outside the catalogs names a specific gun, and nothing in the server loop branches on a gun.

## Package map (`src/main/java/com/modernarmory`)

| package | what lives there |
|---|---|
| `gun` | **What guns are.** `Guns` (THE gun catalog), `GunDefinition` (id, English name, spec, model id), `GunSpec` (+ fluent `Builder`), `GunFamilies` (family templates), `GunView` (sight line / eye / scope), `PartVisibility` (situational model parts: folding BUIS, the M2's tripod), `ScopePower` (issued scope's power range), `ViewClass` (first/third person framing), `GunModels` (what a gun's geo model provides: its `att_<id>` bones), `SoundSet` / `SoundSets` / `Report` (calibre shot sounds). Mechanics as strategies: `FireMode` (+ `FireMode.Trigger`, `TriggerState`), `Feed` (`MagazineFeed` for MAGAZINE / BELT, `TubeFeed` for TUBE; `ReloadContext`, `ReloadTask`), `ProjectileLoad` (SINGLE / PELLETS), `Support` (shoulder / integral bipod / tripod: recoil and spread by stance), `ShooterSpread` (movement spread shared by server and crosshair). |
| `ballistics` | `Cartridge` (+ builder; bullet or shot load) and the `Cartridges` catalog, `CaliberClass` (bore / pressure class muzzle devices are rated for), `DamageModel` (THE damage scale: energy^0.75, anchored on the M4), `ProjectileSpec` (one bullet / pellet in flight), `G7Drag`, `Penetration`. |
| `entity` | `BulletEntity`: the sub-stepped ballistic projectile (drag, gravity, penetration, ricochet, damage, near-miss crack). |
| `item` | `GunItem` (one class for every gun, reads its `GunDefinition`), `AmmoItem`, `GunAnimations` (animation names, trigger / restart). |
| `server` | `GunHandler`: server-authoritative trigger, cyclic rate, ammo and reload loop. Calls the strategies; no gun-specific code. |
| `attachment` | `Attachment` (+ builder), `Attachments` catalog, `AttachmentType` (slots), `GunAttachments` (data component), `GunStats` (spec + attachments = effective stats), `AttachmentItem`. |
| `menu`, `block` | Gunsmith Table. |
| `mastery` | `Mastery` (all mastery rules / numbers), `MasteryHandler` (XP + effects lookup), `GunMasteryData`, `/gunmastery` command. |
| `drone` | **Drones.** `Drones` (THE drone catalog: scout = Skydio X2D, FPV strike drone), `DroneType` (+ builder: speeds, endurance, link range, hitbox, camera, sounds), strategies `DronePayload` (`ReconPayload`: tag targets for the pilot; `ChargePayload`: frag charge with arming delay and contact fuze, blast = `grenade.FragEffect.burst`) and `LinkLoss` (HOVER, RETURN_HOME, FAILSAFE_DROP), `DroneFlight` (the flight model, run by whichever side flies), `DroneLink` (signal from distance and walls, game range cap), `DroneEntity`, `DroneItem` (deploy / hand-launch, battery component), `DroneControllerItem` (pairing, opens the camera view), `DroneControl` (server: who pilots what, actions). |
| `laser` | **Laser air defence.** `LaserSpec` (data: the HELWS turret's power, range, dwell, heat budget, slew, weather derating), `TurretLayout` (the multiblock: cells, model points, placement check), `LaserTurretBlock` (one cell; the whole thing breaks as one), `LaserTurretBlockEntity` (core cell: renders, keeps the head's rest pose), `LaserTurretItem` (places it whole), `TurretSeat` (the operator's seat and the fire control: track, beam, burn, heat). Drones are burned down through `DroneEntity.lase`; jammers use `drone.DroneJamming`. |
| `network` | Payloads (input, actions, recoil, sounds attached to the shooter, mastery sync). |
| `registry` | Deferred registers. `ModItems` registers every gun / ammo / attachment **from the catalogs**; `ModSounds` is the one list of sound events; `ModCreativeTabs` iterates the catalogs. |
| `client` | `ClientState` (input, recoil, ADS maths, scope state, eye box), `GunViews` (optic sight lines from model locators), `ScopeOverlay`, `AttachmentEffects`, `GunCrosshair`, `GunHud`, `ClientMastery`, `GunsmithScreen`, `AutoTest*` (scripted tests). `client/renderer`: `GunRenderer` (GeckoLib, attachment bones, muzzle flash, laser), `ArmSkinLayer` (first-person arms with the player's skin), `BulletRenderer` (tracers). |

Assets: `geo/item`, `textures/item`, `animations/item` are generated per model by
`tools/modelgen` (Fable is not used here). Every build removes z-fighting by itself
(`armorygen.Model.fix_coplanar_overlaps`: where two same-facing box faces share a plane and
overlap, the smaller one is pushed out by 0.02 units; the texture is untouched) and prints the
count per gun; `python tools/modelgen/build.py --check` fails if any overlap is left.
`models/item/<gun>.json` display transforms are
generated by `tools/modelgen/display.py`. Real-world specs with sources: `docs/firearms/specs.json`;
model data (sight line, eye z, slots, animation lengths): `docs/firearms/models.json`.

## Add a gun

1. Model files: `python tools/modelgen/build.py <gun>` (geo / texture / animations).
2. One line in `tools/modelgen/display_items.json`: `"<gun>": {"view": "RIFLE"}` (PISTOL / HEAVY),
   optionally with hand-tuned `gui` / `ground` / `fixed`; `build.py` (or `python tools/modelgen/display.py <gun>`)
   writes `models/item/<gun>.json` from the view class.
3. One catalog entry in `gun/Guns.java`, starting from its family and setting the real specs
   (`docs/firearms/specs.json`) and model numbers (`docs/firearms/models.json`):

```java
/** Glock 17 Gen5: 4.49 in barrel, ~371 m/s, 17 rounds, 0.71 kg empty / 0.91 kg loaded. Sources: specs.json. */
public static final GunDefinition GLOCK17 = add(GunDefinition.of("glock17", "Glock 17", GunFamilies.pistol()
        .muzzleVelocity(371).rpm(185)                // the family sets 9x19, SEMI, magazine feed, report
        .magazine(17).reloadSeconds(1.7, 2.2)        // = the model's animation lengths
        .accuracyMoa(3.5)
        .mass(0.91)                                  // loaded, as carried: it sets the recoil
        .sights(GunView.ironSights(6.5f, 13f))       // models.json sight_y / eye_z
        .slots(MUZZLE, SIDE)));                      // models.json slots (family default otherwise)
```

That is all: the item, creative-tab entry, ammo lookup, HUD, Gunsmith Table slots, mastery,
reload / fire behaviour and the autotest tour come from the catalog. Damage is left unset: it
follows the energy scale (`DamageModel.forEnergy` of one projectile at the muzzle; set
`.damage(x)` only to override). Sounds: `.report(Report.X)` picks the calibre's shot sounds and
gives the gun its own mechanical sounds by convention (`SoundSets.forGun`: `<id>_reload`,
`<id>_reload_empty`, `<id>_cycle` for manual actions), generated by `tools/soundgen/gun_sounds.py`
(add the gun to its `GUNS` table with a kit). Recipes: one line in `tools/datagen/recipes.py`.
Factory-fitted parts: `.fitted(OPTIC, "acog")` (models.json `default_attachments`). The English name is used
when the lang file has no `item.modernarmory.<gun>` entry. Variants reuse a spec and a model:
`M4.spec().toBuilder().fireModes(SEMI, AUTO).mass(3.6)` + `.model("m4")` (the M4A1).

`GunSpec.Builder.build()` throws, naming every missing value (cartridge, velocity, rate,
magazine, reload, damage, accuracy, spread, mass, sights, sounds), and rejects default
attachments in slots the gun doesn't have.

Check it: `./gradlew runAutotest -Pscenario=tour -Pguns=<gun>` (hip / aim / after firing /
mid-reload / third person, plus `[autotest] tour <gun>: ...` ammo bookkeeping and the catalog
check `[autotest] catalog check: N guns, framing + lang + sounds + default attachments ok`).

### Families (`GunFamilies`)

`ar15()`, `battleRifle()`, `boltSniper()`, `dmr()`, `pistol()`, `smg()`, `pumpShotgun()`,
`tubeSemiShotgun()`, `straightPullShotgun()`, `beltFedMg()`, `heavyMg()`, `antiMateriel()`. Each
pre-fills view class, fire modes, feed, attachment slots, typical shooter spread / accuracy,
aim-down-sights time (`adsSeconds`: pistols 0.15 s, rifles 0.2, MGs 0.35, the M2 0.45), support
and, where the family shares one, cartridge and report (`pistol`/`smg` 9 mm, shotguns 00 buck,
`heavyMg`/`antiMateriel` .50 BMG). `ar15` and `boltSniper` keep the recorded M4 / M2010 sound sets;
a gun of those families that calls `.report(...)` gets its own sounds instead (`report` and
`sounds` replace each other). A change to a whole family is one edit there; any setter on the gun
overrides it.

### Mechanics (strategies)

- **Fire mode** (`FireMode`): SEMI, BURST (`burst(n)`), AUTO, BOLT, PUMP, STRAIGHT_PULL. Each is a
  `Trigger` strategy (SINGLE / BURST / AUTO) plus a `manualCycle` flag (mastery XP, "cycle" sound).
  The cycle time is `rpm` (manual actions: `cycleSeconds(s)`, matching the fire animation).
- **Feed** (`Feed`): `MAGAZINE` (whole swap, +1 in the chamber on a tactical reload),
  `BELT` (whole swap, open bolt, no +1), `TUBE` (empty: "reload_empty" chambers one shell, then
  "reload" loops per shell (`reloadSeconds(perShell, chamber)`) until the tube (magazine size) + chamber
  is full or the shooter is out of shells; pulling the trigger with a round chambered stops it and fires).
  New feeds implement `Feed` against `ReloadContext` (no networking / inventory code needed).
- **Projectile load** (`ProjectileLoad.of(cartridge)`): `SINGLE` bullet, or `PELLETS` for a
  cartridge with `pellets > 1`: N `BulletEntity`s, each with the pellet's mass / BC, spread over the
  pattern (`patternMoa` = full diameter), each dealing `damage` (per pellet) scaled by its own energy.
- **Support** (`Support`): how the gun is braced; crouching is the brace. `SHOULDER` (a fitted
  bipod attachment still deploys: x0.35 recoil, half the aimed spread), `BIPOD` (integral bipod,
  same effect without the attachment: M249, M240, M107), `TRIPOD` (M2A1 on its M3 tripod: crouched
  x0.15 recoil; **standing x1.25 recoil (~7 deg per aimed shot, like an M107) and x2.5 spread**, so
  the 38 kg gun is only usable in short bursts unless you get down behind it). `GunHandler` and
  `GunCrosshair` use the same rules.
- **Situational model parts** (`PartVisibility`, `GunSpec.Builder.part(bone, rule)`): `FOLDS_UNDER_OPTIC`
  (folding front BUIS: set by `battleRifle()`, `dmr()`, `antiMateriel()`), `FIRST_PERSON_ONLY` (the
  M2's `tripod` bone: set by `heavyMg()`). `GunRenderer.applyVisibility` applies them; a model without
  the bone ignores the rule, so families set them for all members.
- **Issued scope power** (`GunSpec.Builder.issuedScopePower(min, max)`): the shared `sniper_scope`
  stands in for every issued scope; this gives the factory-fitted one the real gun's power range
  (M110 3.5-10x, M110A1 3-20x, Mk 13 / 21 / 22 5-25x, Mk 20 3.5-15x, M107 4.5-14x). `GunViews`
  applies it only while that factory optic is fitted.
- **Aim time** (`GunStats.adsSeconds()`): the gun's `adsSeconds` divided by the product of its
  attachments' aim-speed multipliers (sniper scope x0.75, ACOG x0.9, angled grip x1.2 ...).
- **Damage** (`ballistics.DamageModel`): one scale for the whole mod, damage = 8 x (E / 1,557 J)^0.75
  per projectile (the M4's M855 = 8): 9 mm ~3.7, 5.56 ~8, 6.8 / 7.62 ~13-15, .300 WM ~20,
  .338 ~23, .50 BMG ~45-48, one 00 buck pellet ~2.2 (x9). `BulletEntity` scales it by the energy
  left at impact with the same exponent.

## Add a cartridge

`ballistics/Cartridges.java`, from `docs/firearms/specs.json`:

```java
public static final Cartridge NATO_9X19 = add(Cartridge.builder("9x19", "9x19mm NATO (M882)")
        .caliber(CaliberClass.PISTOL_9MM).bullet(0.00804, 0.075).powder(0.00036));   // ammo item "ammo_9x19"
public static final Cartridge BUCK_00 = add(Cartridge.builder("12ga_00", "12 Gauge 00 Buckshot")
        .caliber(CaliberClass.GAUGE_12).shot(9, 0.00349, 0.022, 95).powder(0.0018)); // 9 pellets, G7 0.022, 95 MOA
```

The ammo item (`ammo_<id>`, or `.ammoItem("ammo_556")`) is registered automatically, appears in
the creative tab (declaration order), and is what every gun firing this cartridge loads. It needs
`models/item/<ammo>.json` + a 16x16 icon (`tools/texgen/make_textures.py`, `ammo_icons()`) and a
recipe (`tools/datagen/recipes.py`); its name falls back to the cartridge name.

## Add an attachment

`attachment/Attachments.java`: `add(Attachment.of(id, type, name).recoil(0.9f).caliber(...)...)`. Its
geometry is bone `att_<id>` in each gun model (`tools/modelgen/attachments.py`); optics also get a
`sight_<id>` locator, which `GunViews` reads so every optic lines up on every gun. An attachment
fits a gun when (1) the gun has the slot, (2) for calibre-specific parts, the gun's cartridge is of
the attachment's `CaliberClass` (bore / pressure rating, as real cans are rated: the .30 cal
`suppressor_762` fits 7.62x51 M80A1 and M118LR, 6.8x51 and .300 WM guns) and (3) the gun's model
has the bone `att_<id>` (`GunModels`, read from the geo file, so the model is the single source of
what a gun can wear and nothing invisible can be fitted). Icon: `python tools/modelgen/icons.py <id>`;
recipe: `tools/datagen/recipes.py`; lang name.

## Sounds

- **Calibre reports** (`gun.Report`): one enum constant per calibre class (9 mm pistol / SMG, 5.56,
  6.8, 7.62, .300 WM, .338, .50 BMG, 12 gauge), each a bare and a suppressed event registered in
  `ModSounds`, generated by `tools/soundgen/gun_sounds.py` (`REPORTS`: a parameterised shot, volume
  relative to `m4_fire` 0.45).
- **Per-gun mechanical sounds** by convention (`SoundSets.forGun`, picked by `.report(...)`):
  `<id>_reload`, `<id>_reload_empty`, and `<id>_cycle` for bolt / pump / straight-pull guns
  (starts with the shot). `ModSounds.mechanical(name)` registers them on demand while the catalog
  initialises, so a new gun needs no edit in `ModSounds`. `gun_sounds.py` builds each from its kit
  (`MagKit`, `BeltKit`, `ShellKit`; cycles `BoltCycle`, `PumpCycle`, `StraightPullCycle`) on the
  same base timeline as the animation template (`templates.py`), stretched to the gun's animation
  length from `docs/firearms/models.json`, and writes the `sounds.json` entries.
  `python tools/soundgen/gun_sounds.py [name-prefix ...]`.
- **Hand-made sets** (`SoundSets.AR15`, `SoundSets.M2010`): a `SoundSet` built from `ModSounds`
  constants (`fire`, `suppressed`, `reload`, `reloadEmpty`, `shellInsert`, `cycle` + delay; unset
  ones fall back sensibly).
- The autotest catalog check logs `[autotest] sound MISSING` for any event of a gun's set without
  a `sounds.json` entry.

## Recipes

`tools/datagen/recipes.py` is the one table of crafting recipes; it writes both formats
(1.21.1 `{"item": id}` ingredients into `src/main/resources/data/modernarmory/recipe`, 26.3 plain
id strings into `versions/26.3/src/main/resources/data/modernarmory/recipe`) and refuses
conflicting recipes.

## Add / change a view class (first / third person framing)

`src/main/resources/assets/modernarmory/view_classes.json` is the single source: per class the
first / third person display transforms and the hip-fire cant. `ViewClass` reads it at runtime for
the ADS maths (`ClientState.adsX/Y/Z`: eye on the sight line) and the hip cant; `display.py`
writes the same numbers into every `models/item/<gun>.json`. A mod-wide framing change is: edit the
JSON, run `python tools/modelgen/display.py`. A new class: add the enum constant in `ViewClass` and
its JSON entry. The autotest compares every gun's baked item transforms with its class
(`[autotest] framing MISMATCH ...` if someone hand-edits an item model or the mapping drifts).
RIFLE is tuned on the M4 / M2010, PISTOL on the M17 / Glock 17 / Glock 19; HEAVY still holds starting values.

## Drones

Flow: a drone item deploys a `DroneEntity` (right-click a block, or the air to hand-launch) and pairs it with a
Drone Controller in the inventory, which opens the camera view at once (later: right-click the controller).
While the pilot has the link, **their client flies the drone** (`DroneFlight` with the stick input, every tick
a `DronePilotPayload`; the server refuses moves faster than the type can fly and sends `DroneCorrectPayload`);
otherwise the server flies it (the type's `LinkLoss` autopilot, a hover, landing, motors off). The pilot's body
stays put and can be hurt; the HUD shows its health. Client side: `client/DronePilot` (camera entity = drone,
keys -> sticks, left click = payload action, scroll = zoom, B = back to the body, tagged targets outlined for
the pilot only), `client/DroneHud` (camera HUD, picture break-up on a weak link), `client/DroneSounds` (rotor
loops), `client/renderer/DroneEntityRenderer` (rotors, gimbal, tilt).

Add a drone: an entry in `drone/Drones` (real numbers), a model `tools/modelgen/guns/<id>.py` (bones `drone`,
`arm_*`, `rotor_*` on the motor axes, optional `gimbal`; animations `item`, `flight`, optional `armed`;
`tools/modelgen/drones.py`), a `display_items.json` line (view `DEVICE`), rotor sound in
`tools/soundgen/drone_sounds.py` + `ModSounds`, recipe JSONs (both versions), lang. A new payload kind is a
`DronePayload`; a new failsafe a `LinkLoss` constant.

Flight: both drones fly **stabilised** (`FlightMode.STABILIZED`): `DroneFlight` is a rigid-body model (thrust
along the body's up axis = throttle x thrust-to-weight x g, gravity, quadratic drag sized to the type's max
speed) under a flight controller (`stepAuto`): WASD and jump / sneak ask for a velocity (sprint = top speed), the
mouse turns the heading and tilts the camera, and the controller tilts and throttles the airframe to deliver it,
levelling it when the keys are let go; the autopilots (return home, hover, landing) use the same controller.
`.flightMode(ACRO)` on a type gives it acro (rate) controls instead (mouse pitch / roll, throttle stick, no
self-levelling, flips; `stepAcro`, `response(rotTau, expo)`). The view is always the drone's camera (F5 presses only cycle the
perspective the body comes back in). After an FPV detonation a plain strike camera shows the blast for 2 s
(`client/DroneStrikeCam`) if it finds an open vantage point. The pilot hears their drone crash through the
controller wherever their body is.

Link: walls weaken it (`DroneType.wallKeep` per block: 0.9 scout, 0.88 FPV), deep rock (a hillside, a tunnel)
cuts it. A **Drone Relay Antenna** block (`drone/RelayBlock`, model `models/block/drone_relay.json`) placed where it
sees both ends carries the link (`DroneLink.link`: direct or through the best relay; the HUD shows RELAY).

Limits: the link range is capped at 128 m (`DroneLink.GAME_RANGE`) and one chunk inside the view distance,
because the server only sends a player the terrain and mobs around their body.

Check it: `./gradlew runAutotest -Pscenario=drones` (deploy, flight, spotting, link loss and return home,
controller, pickup, FPV arming / impact / air burst; `autotest_drones_*.png`).

## Laser turret

The HELWS laser turret (Raytheon's pallet laser, the US Army's P-HEL) is a 3 wide x 4 deep x 3 tall multiblock:
the turret on its pallet at the front, the operator's cushioned seat and console at the back. Model:
`tools/modelgen/guns/laser_turret.py` (bones `turret` yaw, `director` pitch, locators `aperture`, `seat`; the pivots
are copied into `TurretLayout`). The item is a flat sprite (`tools/modelgen/multiblock_icons.py`).

- Placing: the item puts the seat row on the block aimed at and the turret beyond, facing away from the player.
  `TurretLayout.check` refuses blocked cells, more than 3 bottom cells over a drop, entities in the way, world
  limits and protected spots. While the item is held, `client/LaserOperator` draws a hologram (green fits, red
  blocked, the blocking cells filled red, amber under the drop) and `LaserHud` says why.
- One thing: breaking any cell removes all of them and gives the item back once (in survival); a cell lost any
  other way (explosion, command) collapses the rest the same way.
- Operating: right-click it to sit; the view becomes a sensor camera on a mast above the head (`TurretLayout.SENSOR`),
  aimed by the mouse; scroll zooms; the hand is hidden (the operator's body shows on the seat). Every drone in sensor range gets a
  box (grey without a clear line, amber for what a click would lock). Left click locks the drone nearest the
  crosshair and fires: the head tracks it by itself and holds the beam on it (the view stays free, so the beam is
  seen going out to the drone) until it burns down (dwell from `LaserSpec`, longer at range and in rain). The lock
  breaks when the drone leaves the operator's screen, is out of sight for a second or out of range, or on a right
  click. Not locked, the head follows the operator's look. The laser heats while firing and locks out until cooled.
  Sneak to leave.
- 26.3 differences: geometry is submitted (`SubmitCustomGeometryEvent`), the HUD is a GUI layer, the renderer uses
  GeckoLib 5 render-state tickets, and the seat entity type is saved (26.x only lets entities ride saveable types).

Check it: `./gradlew runAutotest -Pscenario=laser` (refused and accepted placement with the hologram, outside views,
boarding, a scout and an armed FPV burned down, the beam from outside, leaving, collapse; `autotest_laser_*.png`).

## Autotest

`./gradlew runAutotest` runs scenario `core` (the regression baseline: screenshots
`autotest_01..35`, scope mil-scaling and mastery log lines). `-Pscenario=tour -Pguns=a,b` runs the
per-gun tour (`autotest_tour_<gun>_<n>_<what>.png`); without `-Pguns` it tours every catalog gun.
Scenarios are `client/AutoTestCore` and `client/AutoTestTour`; the runner and the script API
(`at`, `cmd`, `shot`, `look`, `buildRange`, ...) are in `client/AutoTest`. Add a scenario by adding
a class with a `script()` and one entry in `AutoTest.SCENARIOS`.
